3. 斷線根本原因決策評估排序（A ~ G）

第 1 順位：[G] 目前證據不足，尚無法最終定論單一根本原因（需補齊登入狀態監控與熱點對照） 信心：高 (90/100)

證據等級：已確認事實

支持證據：
  • 本次自動基準檢查執行時，使用者尚未開啟並登入「新超級大三元」，尚未擷取到斷線當下的即時 Socket 狀態變化。
  • 尚未累積 30 秒週期之長時段斷線時間序列監控紀錄。
  • 尚未進行個人手機熱點（測試 B）對照實驗，依科學診斷原則不得在缺乏對照證據前直接歸咎於學校封鎖。
反證：
  • 已完成本機網路環境、防火牆、Proxy、凱基安裝路徑與官方交易端點（YELLOWPAGE.INI）之完整靜態與連通性基準取證。

第 2 順位：[A] 學校網路出口或防火牆問題（NGFW 協定檢測 / NAT 長連線閒置逾時） 信心：中 (60/100)

證據等級：可能原因

支持證據：
  • 實測發現凱基報價/交易伺服器（gtsfquot.kgieworld.com.tw:443, gtsftrade.kgieworld.com.tw:443, gtsquot.kgieworld.com.tw:443, gtstrade.kgieworld.com.tw:443）雖使用 TCP 443/80 通訊埠，但並非標準 HTTPS/TLS 交握，而是凱基 HTS 專屬加密長連線協定（axsock.ocx / TS070300）；校園次世代防火牆（NGFW App-ID / Application Control）常將 Port 443 上的非標準 TLS 長連線識別為 unknown-tcp 或異常協定，進而套用極短閒置逾時（如 30~120 秒）或週期性中斷連線。
  • 本機網路環境辨識具學術網路（TANet 140.x）或企業級 802.1X 網路特徵。
反證：
  • 目前初次 TCP 三方交握對全部 8/8 個凱基端點均可連通，證實學校防火牆並未『完全靜態封鎖』凱基伺服器 IP 或 Port 80/443（若有關聯，較可能為長連線 NAT 狀態逾時或 NGFW 深度協定檢測中斷，而非靜態黑名單）。

第 3 順位：[F] 交易系統自身閒置逾時、換盤清盤或同帳號跨裝置（手機 App）Session 互踢 信心：低 (20/100)

證據等級：可能原因

支持證據：
  • 靜態設定檔 tab/HTSWORK.INI 定義有盤後交易開盤清盤重載機制（FOCLR），特定換盤時段會提示或觸發畫面重載。
  • 證券交易軟體普遍具有『單一帳號重複登入互踢（手機 App 三竹/隨身 e 策略與電腦版同時登入同一組身分證）』或『交易 Session 閒置逾時保護』機制。
反證：
  • 尚未經由長連線監控排除

第 4 順位：[B] DNS 解析異常或系統/透明 Proxy 干擾問題 信心：低 (15/100)

證據等級：可能原因

支持證據：
  • 目前未偵測到本機 Proxy 或 DNS 解析失敗
反證：
  • 本機 WinINET 系統 Proxy 未啟用，且無設定 PAC 自動組態網址。
  • 本機 WinHTTP 為直接存取（Direct access，無代理伺服器）。
  • 公開 HTTPS 網站（凱基官網、Microsoft、GitHub）憑證簽發者皆為合法公開 CA，未偵測到透明 SSL MITM 憑證替換。
  • 過去 24 小時系統日誌無 DNS Client 1014 解析逾時紀錄，且凱基網域目前皆可正常解析。

第 5 順位：[D] Windows 本機防火牆、端點安全軟體、VPN 或網卡省電/睡眠設定問題 信心：低 (15/100)

  • 目前未偵測到第三方 VPN 或本地代理工具（如 Clash/WireGuard/OpenVPN）在背景執行。
