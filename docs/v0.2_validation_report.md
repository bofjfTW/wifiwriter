# wifiwriter v0.2 修正驗證報告與 Git 歷史隱私風險評估 (`docs/v0.2_validation_report.md`)

## 一、基準狀態與 v0.1 問題審查摘要

本次審查以儲存庫初始提交（`main` @ `a1264fb`）為基準：
- **現有實測事實：** 五個預設公開網站通過連線檢查；八個凱基靜態設定候選端點（4 個網域 × Port 80/443）初次 TCP 建連成功；檢查當下凱基交易軟體**未啟動**，因此**沒有任何實際交易 TCP Socket 證據**，亦**尚未執行校園網路與手機熱點 A/B 對照實驗**。
- **v0.1 修正前之關鍵缺陷（已於 v0.2 全數修正）：**
  1. **斷線定義混淆（P0）：** 舊版 `monitor_connections.ps1` 使用 `$isOutageNow = (-not $netUp -or $appDropped -or $probeFailed)`，導致即使交易程式未開啟，單次獨立 TCP 探測失敗也會被計入交易斷線，並以 `總時間 ÷ (斷線數+1)` 虛構平均連線時間。
  2. **過度推論專屬協定與防火牆攔截（P0）：** 舊版 `diagnostics.py` 與 `analyzer.py` 在 TCP 443 連通但標準 TLS 失敗時，直接宣稱「採用 HTS 專屬二進位協定」並替校園防火牆（Cause A）加上任意數值信心分數（`score_a`）。
  3. **GitHub 自動同步隱私風險（P0）：** 舊版 `AGENTS.md` 要求自動推送 `main`，且 `sync_github.ps1` 使用無限制 `git add -A`，致使 14 份本機診斷報告檔案進入初始 Commit `a1264fb`。
  4. **監控生命週期與過期資料問題（P1）：** 舊版未防止重複啟動背景監控、未驗證 PID 建立時間、未處理子程序非零結束碼，且 `compare_ab_results()` 缺少科學可比性前置檢核與每小時標準化率。

## 二、Git 歷史（Commit `a1264fb`）隱私風險評估與處置方案（P0 重點）

### 2.1 已進入 Git 歷史之檔案風險盤點

在初始 Commit `a1264fb`（目前仍位於遠端 `origin/main`）中，包含根目錄 `network_environment.{json,md}` 與 `reports/` 下共 14 個診斷輸出檔案。經逐檔安全審查：

- **未外洩之高敏感項目（低立即金融風險）：**
  - 無任何證券帳號、密碼、身分證字號、Cookie、Session Token、憑證私鑰或委託紀錄。
  - Windows 使用者名稱與電腦主機名稱已遮罩為 `<USER>` / 首尾碼遮罩，MAC 位址後三組與客戶端 IP 末兩段亦已遮罩為 `xxx.xxx`。
- **仍存在之環境指紋辨識風險（中度隱私指紋風險）：**
  1. 保留了台灣學術網路（TANet）前兩段 `/16` 前綴（可直接辨識特定大學校區網段）。
  2. 包含精確到秒之系統上次開機時間、Windows 組建版號（Build.UBR）、實體乙太網卡晶片型號與驅動程式版本。
  3. 包含本機軟體安裝磁碟機代號、安裝時間戳記，以及一筆歷史加密日誌之檔名（含日期時間與歷史 PID）。

### 2.2 為何新增 `.gitignore` 或刪除最新版檔案「無法」消除 Git 歷史紀錄？

在本分支 `fix/diagnostic-reliability-v02` 中，我們已透過 `git rm --cached` 將上述 14 個檔案自**新版 Git Index（暫存區）移除**（同時完整保留使用者硬碟上的本機檔案與 `reports/local_v01_backup/` 備份），並更新 `.gitignore` 與 `src/privacy.py` 阻擋未來任何報告檔案被追蹤。

**但必須明確指出：這並不會消除 Git 歷史中的既有資料。** 原因如下：
1. Git 是不可變的內容可尋址物件資料庫（Content-Addressable Object Store）；Commit `a1264fb` 的 Tree 物件與對應的 14 個 Blob 物件仍完整存在於 `.git/objects` 與 GitHub 伺服器上。
2. 任何擁有公開儲存庫讀取權限的人（或爬蟲），只需檢視歷史 Commit（`git log -p a1264fb` 或瀏覽 GitHub Commit `a1264fb` 網頁），依然能完整檢視該批檔案內容。

### 2.3 清除 Git 歷史之可行方案與影響評估（未經授權絕不自行 Force Push）

若您希望徹底從公開 GitHub 抹除 `a1264fb` 中的歷史報告 Blob，請評估以下兩種方案並明確指示後再執行（**依安全規範，本工具絕不自行執行 `git push --force`**）：

- **方案 A：使用 `git filter-repo` 重寫歷史並強制更新遠端**
  - **作法：** 在本機備份整個資料夾後，執行 `git filter-repo --invert-paths --path reports/ --path network_environment.json --path network_environment.md`（保留 `reports/.gitkeep`），再由您授權執行 `git push --force --all origin`。
  - **影響：** 所有既有 Commit SHA-1 雜湊值都會改變；若有其他協作者已 Clone 此 Repo，需重新 Clone。此外，若需立即清除 GitHub 端孤立 Commit 快取，需於 Force Push 後向 GitHub Support 請求清除懸空物件（Dangling Commits GC），或刪除重建遠端 Repo。
- **方案 B：在 GitHub 重新建立乾淨儲存庫（或將儲存庫改為 Private）**
  - **作法：** 最簡單且零殘留快取風險的方式，是在 GitHub Settings 將 `wifiwriter` 設為 **Private（私有儲存庫）**；或刪除遠端舊 Repo 後新建同名空白 Repo，僅推送乾淨的 v0.2 程式碼分支。
  - **影響：** 原有 Issue / PR 編號會重置（目前 Repo 剛建立，幾乎無歷史負擔）。

## 四、測試執行結果統計

- **已通過項目（17 / 17 通過，0 失敗）：**
  1. 凱基未啟動 + 探測失敗 → 輸出 `KGI_PROBE_FAILURE`（`探測失敗，尚無交易程式斷線證據`），已確認斷線數 `= 0`。
  2. 凱基執行中 + 公開對照網站失敗 → 獨立歸類為 `CONTROL_ENDPOINT_FAILURE`。
  3. TCP 443 成功但 TLS Timeout / Reset / EOF → 分別記錄細分狀態，`application_protocol = UNKNOWN`，且不膨脹防火牆推論。
  4. Socket 正常開啟與關閉輪替但無斷線回報 → 正確統計建立/結束次數與可辨識秒數，不計入已確認交易斷線。
  5. 程式退出（`KGI_PROCESS_EXITED`）與既有 Socket 中斷（`KGI_SOCKET_DISCONNECTED`）嚴格分離；未知起點連線顯示 `無法精確估計`。
  6. 背景監控重複啟動保護 → 第二次啟動立即回傳 Exit Code `3`（`CONFLICT`），不破壞原監控。
  7. 舊殘留 Stop Flag 清除、優雅停止（`Stop`）原子保存完整資料，以及背景程序異常消失（PID / StartTime 驗證）自動標記 `FAILED`（Exit Code `4`）。
  8. PowerShell 子程序回傳非零 Exit Code → 立即中止、回傳非零碼並寫入去識別化之 `error_summary.json`。
  9. 過期舊報告（Run ID 不符或跨日資料）驗證攔截與 `PARTIAL` 降級。
  10. A/B 樣本數為 `0` 檢核攔截。
  11. A/B `label` 與實際網路環境不符檢核攔截。

  13. `src/privacy.py` 敏感資訊與 Git 白名單路徑掃描驗證。
  14. Markdown / HTML / CSV / Sanitized JSON 報告零原始金融與個人敏感資料洩漏驗證。
